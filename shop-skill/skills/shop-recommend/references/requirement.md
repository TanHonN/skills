# 需求澄清规则

## 问题识别

- 用户问题: 优先记录用户原始描述的问题、麻烦、不便、风险或想改善的体验，不直接替换成商品名称。
- 真实目标: 从用户问题中提炼要达成的效果，例如节省时间、节省空间、提升舒适度、降低风险、减少损耗、改善效率或提升稳定性。
- 使用对象: 明确物品给谁使用，例如本人、家人、儿童、老人、宠物、同事或访客；使用对象会影响安全性、尺寸、材质和复杂度。
- 使用场景: 明确使用地点、频率、环境和持续时间，例如家用、通勤、办公、宿舍、厨房、车内、旅行或户外。

## 约束条件

- 预算范围: 用户已给预算时按预算筛选；未给预算时先按基础可用、性价比和品质升级三个层级组织建议。
- 空间尺寸: 涉及摆放、收纳、安装、携带或适配时，应确认可用空间、尺寸限制和安装条件。
- 使用偏好: 关注外观、噪音、重量、操作难度、清洁难度、耗材成本、耐用性、便携性和维护成本等偏好。
- 排除条件: 记录用户明确不接受的物品类型、品牌、材料、功能、价格区间、操作方式或使用限制。
- 已尝试方案: 记录用户已经买过、用过或排除过的方案，并确认不满意原因。

## 澄清方式

- 信息足够: 用户需求足以判断物品类型时，直接给出推荐，并在结果中标注默认假设。
- 信息不足: 缺少关键约束会明显影响推荐方向时，先询问少量必要问题；不要把所有可能字段一次性追问完。
- 默认假设: 用户未说明非关键条件时，可以使用常见生活场景假设，但必须在输出中说明假设范围。
