# Playwright 循环规则

## 关注点

本规则关注“如何为本轮任务编写 Playwright 循环脚本”。脚本是任务专用产物；用户未指定任务工作区时，放入临时目录并向用户说明路径，不写入 skill 目录或无关业务项目。

## 脚本结构

任务脚本应包含以下职责单元：

1. 运行准备: 确认脚本具备运行条件并固定任务配置。
   - 运行前提: 确认当前环境可以运行 Playwright；若需要安装依赖、启动新浏览器或改动项目依赖，先向用户说明影响并等待确认。
   - 目标配置: 写明目标 URL 或页面接管方式、检查间隔、最长运行时间和最大重试次数。
   - 证据配置: 写明截图目录、日志路径和任务契约摘要。
2. 循环主体: 在任务契约范围内读取状态、判定状态并执行允许动作。
   - 页面准备: 打开或连接目标页面后，只执行任务契约允许的导航、定位和准备动作；触发任务契约定义的暂停条件时退出循环。
   - 状态读取: 使用 Playwright `locator` 读取目标区域的可见文本、按钮状态、列表状态、禁用状态和错误提示。
   - 状态判定: 将页面状态归一为下文定义的状态值。
   - 动作执行: 只执行任务契约列出的低频页面动作，并在动作前后记录页面状态。
3. 证据收口: 记录每轮证据并在结束时给出可接管结果。
   - 轮次记录: 每轮记录时间、状态、关键文本、动作、失败原因、重试次数和截图路径。
   - 退出处理: 达到成功、暂停、超时、失败上限或用户停止条件时，输出最终状态和接管说明。

## 状态读取

- 定位策略: 优先使用可读、稳定的页面信号定位元素。
  - 优先定位: 使用 `getByRole`、`getByText`、`getByLabel` 和稳定的业务文本。
  - 兜底定位: 只有页面没有可读信号时，才使用 CSS 选择器，并在日志中说明依据。
- 读取范围: 只读取任务契约中的观察区域、目标状态信号和暂停条件信号。
- 结构变化: 页面跳转、弹窗、新标签页或步骤变化后，重新读取页面身份信号，再继续判定或退出循环。

## 状态判定

- `waiting`: 目标机会尚未出现，页面仍可继续按契约观察。
- `candidate-found`: 页面出现任务契约定义的候选机会，脚本停止并提醒用户接管。
- `needs-human`: 页面进入登录、验证、确认、高影响动作或其他人工处理节点。
- `blocked`: 页面出现平台限制、访问异常、排队限制或账号风险提示。
- `completed`: 任务契约定义的终止状态已经达成。
- `error`: 脚本无法读取关键状态、`locator` 失效或出现未处理异常。
- `stopped`: 达到最长运行时间、最大重试次数、连续失败上限或用户停止条件。

## 动作执行

- 操作依据: 每次动作前重新读取目标对象和当前状态，确认仍符合任务契约。
- 操作频率: 使用任务契约约定的检查间隔；每轮循环仅执行一次状态读取和一次契约允许动作。
- 操作验证: 动作完成后记录当前 URL、关键文本、状态值和截图路径。
- 失败处理: 连续失败达到契约上限时退出循环，保留当前页面、日志和截图，交由智能体分析。
