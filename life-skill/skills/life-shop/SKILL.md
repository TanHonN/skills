# 电商比价

按以下流程执行，不要跳步。

## 概览

围绕用户指定的商品做跨平台搜索、同款确认和可信度过滤，输出可追溯的比价结果。重点不是单纯找最低标价，而是找“规格一致、当前账号能买到、店铺可信”的候选商品。

## 前置条件

- 先确认当前环境有可用的浏览器自动化能力，例如 Chrome DevTools 类工具；若没有，则说明此 skill 当前无法执行。
- 先确认用户允许使用浏览器访问目标购物平台。
- 先确认本轮目标是“比价与信息收集”，不是下单、加入购物车、领券、入会或关注店铺。
- 先提醒用户：若平台尚未登录、需要扫码、短信验证、滑块验证或二次确认，应由用户手动完成。
- 若用户已经登录多个购物平台，优先复用当前登录状态；不要主动退出用户账号，不要切换成其他账号。

## 开始前确认

开始前，优先确认以下信息；如果用户已经说清楚，则不要重复追问。

- 商品关键词：用户想比价的商品名称
- 同款约束：品牌、型号、容量、颜色、版本、套餐、赠品、保修和发货方式
- 目标平台：默认比较京东、拼多多、淘宝/天猫、抖音商城
- 平台列表确认：先列出本轮当前考虑的平台，并顺便询问用户是否要新增、删除或替换平台；若用户未提出调整，则沿用当前平台列表继续
- 收货地区：若价格和运费会受地区影响，默认以当前账号的默认收货地区为准
- 价格口径：默认比较当前登录账号在页面上可见、普通用户可获得的到手总价
- 可信度阈值：若用户未指定，使用默认阈值

默认可信度阈值如下：

- 优先推荐自营、官方旗舰店、品牌旗舰店、官方店
- 对非官方店铺，若店铺粉丝数低于 1000，则不放入推荐结果
- 对非官方店铺，若商品评价数低于 50，则不放入推荐结果
- 若页面展示好评率，低于 95% 的候选不放入推荐结果
- 若粉丝数、评价数、好评率等关键字段缺失，除非该店铺明确是官方或自营，否则只记为“观察项”，不进入推荐结果

## 执行流程

### 1. 为每个平台创建并行子智能体

- 默认采用“一个平台对应一个子智能体”的方式并行执行；每个子智能体只负责一个购物平台。
- 创建或调用子智能体时，准备派生、能力与上下文配置、任务派发、执行管理和结果处理遵守 `$agent-subagent-dispatch`；平台并行和浏览器实例约束按本 skill 处理。
- 每个子智能体都应打开一个独立的 Chrome 实例，不要复用同一个实例去串行访问多个平台。
- 若当前环境无法并行打开多个独立 Chrome 实例，先暂停并提醒用户检查 `chrome-devtools-mcp` 是否启用了 `--isolated=true`；若刚修改配置，提醒用户重启当前 Codex 会话后再试，并顺便询问用户是否接受改为单个智能体串行访问各平台；若用户既未修复配置也不接受串行执行，应明确说明本轮无法按默认并行流程执行。

### 2. 子智能体打开平台并确认登录状态

- 各子智能体分别打开自己负责平台的首页或搜索页。
- 若平台未登录、登录失效、触发验证码或滑块验证，立即暂停，等待用户手动处理。
- 不要尝试自动输入账号密码，不要绕过验证码、短信验证、人机验证或其他平台风控。
- 子智能体在继续搜集价格前，必须明确等待用户完成登录或验证，不要在未登录状态下继续抓取不完整结果。
- 若某个平台始终无法登录或页面无法打开，向主智能体明确说明该平台本轮未纳入结果。

### 3. 搜索并收集候选商品

- 在各平台使用同一组商品关键词搜索。
- 默认优先查看前 5 个到 8 个非广告候选；若前几项明显不是同款，再适度向下扩展。
- 优先跳过“广告”“赞助”“直播引流位”“限时活动会场入口”等不稳定入口；只有进入具体商品详情页并确认是同款后，才能纳入候选。
- 对每个平台，至少收集以下信息，并以结构化结果返回给主智能体：
  - 商品标题
  - 商品链接
  - 店铺名
  - 店铺类型
  - 页面可见标价
  - 页面可见优惠信息
  - 运费或包邮信息
  - 粉丝数、评价数、好评率等可信度指标

### 4. 先做同款判定，再做价格比较

必须先确认是同一商品，再比较价格。至少核对以下信息：

- 品牌
- 型号
- 规格或容量
- 颜色或版本
- 套餐或赠品
- 是否全新
- 是否预售、订金、拍下改价、企业采购专享或入会专享
- 发货地、保修方式和服务承诺是否存在明显差异

默认排除以下候选：

- 二手、翻新、样机
- 预售、订金、尾款未计入的商品
- 需要入会、成为新客、使用特定支付方式或叠加复杂凑单后才能达成的价格
- 规格不完整或标题明显模糊的引流款
- 无法确认是否同款的候选

若两个候选高度相似但无法 100% 确认是否同款，标记为“待确认”，不要强行纳入推荐结果。

### 5. 统一价格口径

默认按以下口径计算和汇报：

- 到手总价 = 当前可见商品价格 - 当前页面明确可领可用的优惠 + 运费
- 若页面展示包邮，则运费记为 0
- 若某价格依赖 PLUS、88VIP、新客、直播间、店铺会员或其他特殊身份，单独标注，不与普通用户价混为一谈
- 若优惠需要复杂凑单、跨店满减或拍多件才能成立，单独标注条件，不直接当作基准价

不要只比较标价。若某个平台无法明确给出普通用户的到手总价，说明不确定项并降低该候选的可比性。

### 6. 评估店铺可信度

在价格之外，至少结合以下因素评估是否值得推荐：

- 店铺类型：自营、官方旗舰店、品牌旗舰店、官方店优先
- 店铺粉丝数或关注数
- 商品评价数或已售量
- 店铺或商品好评率
- 页面信息是否完整、是否存在明显异常营销表述

若页面字段名称和位置与预期不同，先读取 [platform-signals.md](./references/platform-signals.md) 获取平台差异提示，再结合实际页面判断。字段缺失时不要猜测，直接标记为未知。

### 7. 主智能体汇总并输出比价结果

- 主智能体负责汇总各子智能体返回的结构化结果，并统一完成同款对齐、价格口径归一和可信度筛选。
- 若不同子智能体返回的信息字段完整度不一致，主智能体应保留缺失标记，并在最终结果中说明哪些平台的数据不完整。

默认输出一个结构化表格，并在表后给出简短结论。表格至少包含：

- 平台
- 商品标题
- 店铺名
- 店铺类型
- 是否确认同款
- 到手总价
- 运费
- 优惠或限制条件
- 粉丝数
- 评价数或已售量
- 好评率
- 是否推荐
- 不推荐原因或风险说明
- 商品链接

在结论中明确说明：

- 当前最便宜的可信同款是哪一个
- 哪些候选虽然更便宜，但因为店铺质量、价格条件或规格不一致而不推荐
- 哪些平台因为未登录、风控、地区价或字段缺失导致结果不完整

## 行为约束

- 不要下单、加入购物车、收藏、关注店铺、领取会改变账号状态的优惠或加入会员
- 不要为了凑低价而主动修改用户地址、支付方式、会员状态或账号设置
- 不要绕过验证码、风控、登录校验或其他平台限制
- 不要把不同规格、不同套餐或不同服务承诺的商品当作同款
- 不要把会员价、新客价或直播间专享价伪装成普通用户可得价格
- 不要在字段缺失时编造粉丝数、评价数、好评率或销量
- 不要只因为价格最低就推荐低信誉店铺

## 停止条件

出现以下情况时停止继续扩展并向用户汇报当前结果：

- 每个平台已经找到 3 个以上可信同款候选
- 关键平台出现无法人工处理的登录或验证码阻塞
- 多个平台都无法确认同款，继续搜索收益很低
- 页面反复刷新、字段不稳定或疑似触发平台风控
