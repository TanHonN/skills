# 问题分析流程

## 递进过程

问题分析按业务领域、问题或需求、分析、设计、实现逐步细化。每个阶段先明确分析对象的组成，再推进到当前信息能够支持的状态；后续阶段获得的新信息可以回流修正前序判断。

设计和实现分别负责形成解决方案和产生可观察、可验证的结果，是各类问题分析过程的组成。

### 业务领域

业务领域是问题发生或需求提出的现实或抽象场域，用于确定当前问题或需求的范围、对象组成和规则约束。

#### 组成

- 概念: 领域中被反复使用和判断的核心对象、术语、状态或事件。
- 参与者: 在领域中产生动作、承担责任、接收影响或提供资源的人、组织、系统或角色。
- 资源: 被参与者创建、消耗、占用、流转或维护的材料、数据、能力、时间、资金或工具。
- 规则: 约束参与者变化、资源流转、协作方式和有效性判断的条件。
- 状态: 领域对象在不同时间点呈现出的情况，以及状态之间的变化路径。
- 外部约束: 来自相邻领域、组织环境、技术环境、法律政策或现实条件的限制。

#### 推进步骤

1. 确定领域边界: 说明当前分析覆盖的业务对象、参与者和场景，以及排除的相邻领域。
2. 识别领域组成: 列出领域内的核心概念、参与者、资源、规则、状态和外部约束。
3. 分析概念结构: 判断概念之间的单元、关系、边界、行为和生命周期，避免停留在名称解释。
4. 分析协作关系: 判断参与者使用资源、遵守规则、改变状态和相互影响的方式。
5. 标出领域约束: 记录会限制后续问题或需求、分析、设计和实现的稳定条件。

### 问题或需求

问题是导致现象不符合预期的原因；需求是针对问题提出的期望改变、成功标准、约束和使用对象。二者位于同一层级，当前任务通常以其中之一作为入口；当前判断依赖二者关系时，建立对应关系。

#### 组成

- 对象与目标: 确定当前处理对象及其变化目标。
  - 入口对象: 判断当前材料主要表达问题还是需求，并明确本轮需要形成的问题、需求或二者对应关系。
  - 现象与预期: 说明实际观察到的状态或行为、对应预期，以及二者之间的差异。
  - 期望改变: 说明从当前状态转向目标状态的变化目标，以及这种改变服务的结果。
  - 成功标准: 说明判断需求满足所需的结果、行为、指标、证据或验收条件。
- 影响与条件: 确定问题或需求涉及的对象和成立条件。
  - 影响对象: 说明被问题影响的参与者、资源、流程、结果或判断。
  - 使用对象: 说明需求由谁使用、服务谁或作用于哪些参与者、资源、流程或结果。
  - 成立条件: 说明问题出现或需求成立时对应的场景、时间、规模、状态或约束。
- 原因与约束: 确定问题的原因和需求受到的约束。
  - 问题原因: 说明使当前问题形成、持续或变化的更深层领域机制、协作关系、规则、状态变化或知识缺口。
  - 需求约束: 说明需求成立时不能破坏的领域规则、资源条件、时间条件和外部限制。

#### 推进步骤

1. 确认入口对象: 判断当前材料主要表达问题还是需求，并明确本轮需要推进的对象。
2. 完善对象依据: 当前对象为问题时，补齐现象与预期、影响对象和成立条件；当前对象为需求时，补齐期望改变、使用对象和成立条件。
3. 定位问题关系: 当前对象为问题时，定位问题及其更深原因；当前对象为需求且当前判断依赖其问题依据时，回溯需求回应的问题。
4. 形成结果口径: 当前对象为需求，或需要由问题进入方案或验收时，明确期望改变、成功标准和需求约束。
5. 区分对象与方案: 将待解决问题或需求与候选解决方式分开，并暴露仍缺少证据的问题条件、影响范围和边界。

### 分析

分析是从问题或需求出发解释其成立条件、作用机制、影响和证据强度的过程，用于判断需要改变的机制或需求是否成立。

#### 组成

- 事实: 已确认的现象、材料、数据、行为、上下文或来源。
- 条件: 影响问题表现、需求成立范围或分析结论的前提。
- 机制: 条件作用于领域组成并导致结果的过程。
- 因果链: 相关事实、条件、机制、影响和结论之间的连接关系。
- 证据: 支撑判断的事实来源、查证结果、实验数据、代码行为、文献或经验。
- 假设: 尚未查证但会影响分析结论的前提。
- 反例: 会削弱当前解释、指向替代解释或暴露失败条件的材料。

#### 推进步骤

1. 汇集事实材料: 区分已确认事实、上下文材料、经验判断和推测内容。
2. 建立因果链: 说明条件、机制和影响之间的连接关系，不从现象或需求直接跳到方案。
3. 标注证据强度: 判断证据能支持多强的结论，证据不足时保留适用边界。
4. 暴露关键假设: 把无法查证但会改变结论的前提单独列出。
5. 用反例修正: 检查替代解释、相邻方法、失败条件和证据冲突，必要时回到问题或需求重新界定。

### 设计

设计是把分析结论转化为方案结构、职责分配、边界约束和取舍依据的过程。

#### 组成

- 目标机制: 方案准备改变或利用的关键机制。
- 职责单元: 方案中承担独立职责的模块、步骤、角色、文档、工具或规则。
- 协作关系: 职责单元之间的信息、资源、动作、约束和结果传递方式。
- 边界: 每个职责单元的负责范围、排除范围、对外暴露内容和依赖对象。
- 行为: 方案在关键场景下产生的可观察动作和结果。
- 状态与生命周期: 方案对象的产生、变化、完成、失效和维护方式。
- 取舍: 多个方案在成本、风险、可逆性、扩展性和验证方式上的差异。

#### 推进步骤

1. 回到分析结论: 明确设计要回应的问题机制或需求目标，以及对应约束和成功标准。
2. 划分方案组成: 按职责单元、协作关系、边界、行为和生命周期组织方案结构。
3. 校验边界关系: 检查职责是否混杂、依赖关系是否合理、边界是否明确、状态归属是否清楚。
4. 说明方案取舍: 比较候选方案在代价、风险、扩展空间和回退方式上的差异。
5. 设计验证路径: 说明后续用于判断设计成立的证据、测试、实验、评审或反馈。

### 实现

实现是把设计落到可观察行为、可交付产物或可执行动作，并通过反馈检验前序判断的过程。

#### 组成

- 产物: 实现阶段交付的代码、文档、流程、实验、配置、决策或其他可复查结果。
- 动作: 为生成产物而执行的修改、运行、验证、沟通、记录或发布行为。
- 依赖: 实现需要使用的资源、工具、环境、权限、输入材料和前置条件。
- 实现结果: 产物或动作在目标场景中产生的可观察结果或影响。
- 验证结果: 对照问题或需求、分析和设计得到的证据、差异、风险或失败结果。
- 反馈信息: 实现过程中发现的新事实、新限制、新机会或新反例。

#### 推进步骤

1. 形成可验证结果: 形成能够验证关键设计判断的产物或动作。
2. 连接前序判断和设计: 说明实现结果与问题或需求、分析结论和设计结构的对应关系。
3. 检查实现结果: 用事实、运行结果、评审反馈或其他证据判断实现是否符合预期。
4. 记录反馈信息: 将实现中的新限制、新事实或失败结果作为前序阶段的输入。
5. 回流修正判断: 当实现反馈推翻原有判断时，回到问题或需求、分析或设计修正，并同步调整依赖原有判断的实现结果。

### 迭代推进

问题分析过程按 `$principle-iterative-process` 逐轮推进。本节说明新信息如何在业务领域、问题或需求、分析、设计和实现之间回流。

#### 回流对象

- 新信息: 任一阶段新增的事实、证据、限制、反例、反馈或外部变化。
- 受影响阶段: 新信息改变的业务领域、问题或需求、分析、设计或实现阶段。
- 回流入口: 新信息应进入的阶段，以及该阶段中需要修正的对象、边界或判断。
- 依赖结果: 后续阶段中依赖被修正判断的结论、方案或实现结果。

#### 推进步骤

1. 定位受影响阶段: 判断新信息直接改变的阶段及其具体内容。
2. 修正阶段内容: 将新信息纳入受影响阶段，并更新相应对象、边界、关系或判断。
3. 同步依赖结果: 调整后续阶段中依赖原有判断的内容，再把更新后的状态交给下一轮迭代。
