# 对象结构原则

## 关注点

当任务需要理解、拆分、设计或复核一个对象时，应判断对象的稳定单元、单元协作方式、边界划分、行为和状态归属，以及生命周期的开始、变化和结束。

这里的对象可以是任何事物，例如代码模块、研究问题、文档、计划、流程、组织、产品能力、业务概念或其他可被分析的事物。

## 结构维度

### 单元

单元是对象中能独立说明用途的组成部分。识别单元前，应明确分析对象和当前目标，使单元划分服务当前判断。

- 稳定关注点: 单元应围绕稳定关注点形成，而不是按临时表面形态拆分。稳定关注点可以是业务对象、问题机制、流程阶段、职责能力、信息结构或资源边界。
- 独立说明: 一个单元应能说明自身用途、负责内容和不负责内容，不能只依靠所在文件、章节、目录、组件或表面类型成立。
- 拆分边界: 当一个部分同时承载多个不同关注点时，应继续拆成更准确的单元；当多个部分服务同一稳定关注点时，应优先聚合。

### 关系

关系说明单元之间如何发生联系，例如包含、并列、调用、依赖、约束、转化、因果、竞争或支撑。

- 关系依据: 识别关系时，应说明其成立依据、连接方式和相互影响；分类结果只说明共同属性，不构成单元之间的关系。
- 层级是关系形态: 整体与部分、抽象与具体、上层关注点与下层实现都属于关系表达，应说明上下层如何连接，而不是把层级当作独立组成类型。
- 依赖方向: 涉及上下游、抽象与具体、目标与手段时，应说明依赖主体和被依赖对象，避免局部实现约束整体结构。

### 边界

边界说明每个单元的负责范围、排除范围，以及外部可靠使用该单元的方式。

- 输入输出: 说明单元接收的输入、产生的输出，以及输入输出的稳定格式或约束。
- 可见性: 说明单元的对外可见部分、内部使用部分，以及外部可依赖的公开契约。
- 状态与错误: 说明状态归属、状态变化范围、失败表达、例外条件和责任终点。
- 约束与副作用: 说明外部依赖、环境条件、资源访问、全局影响或其他副作用归属于哪个单元。
- 层级边界: 当结构存在上下层时，应说明上层表达的目标、约束和判断依据，以及下层承载的实现、材料、动作或细节。

### 行为

行为是对象或单元产生的动作、结果或副作用。

- 行为归属: 根据行为目标、相关状态、约束来源和后果承担主体确定其所属单元。
- 跨单元协作: 跨单元行为应说明参与单元各自承担的职责，以及行为和结果如何在单元之间传递。

### 生命周期

生命周期说明对象或单元如何产生、变化、失效、释放、归档或被替换。只描述静态组成而不说明生命周期，会导致状态归属、边界和行为后果不完整。

- 起点条件: 说明对象或单元的创建主体、前置条件，以及进入有效状态的时点。
- 变化过程: 说明状态如何迁移，哪些行为、事件、输入或环境变化会影响它。
- 终点责任: 说明对象或单元何时失效、释放、清理、归档或被替换，以及终点动作的责任主体。
